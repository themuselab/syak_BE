## 1. 관리자 페이지 라이트 테마 리디자인 + 마케팅 탭 신설

**요청**: 다크 글래스 → 라이트 테마 + 상단 네비 + 핑크 브랜드(목업 기준)로 재디자인. 배포 말고 확인용 개발서버. 마케팅 탭 추가(인스타/쓰레드/메타광고 성과, AI 조언, 발행 이미지 관리).

**진행**:
- 관리자 SPA 전면 라이트 테마 전환(top-nav, 핑크 브랜드 토큰). Sidebar/Stats(데드코드) 제거.
- 마케팅 탭: 메타 광고 카드(클릭 시 추세 모달) → 인스타/쓰레드 반반(실제 브랜드 아이콘, 계정 링크) → 게시물 Top → 발행 이미지 갤러리(무한 가로 슬라이드, 다운로드/삭제).
- 대시보드 차트 목업에 맞춤(둥근 캡슐 바, 피크 강조, 8개 라벨 전부, 브랜드 핑크 통일).
- 종 알림: 검토 대기 도입 문의 있을 때만 초록(SSE 실시간). 첫 진입 시 전날 리포트 모달("오늘 하루 보지 않기").
- 전체 샵 DB: 카테고리·지역을 **정렬이 아니라 드롭다운 선택**(시/도→시군구 2단계, DB 파생), 전화번호(`detail.phone`) 표시, 행/열 버그 수정.

## 2. 마케팅 자동화 (GitHub Actions로 매일 수집)

**요청**: 인스타/쓰레드/메타광고 지표를 수집→Gemini 조언→Supabase 날짜별 저장. 처음엔 수동 스킬 생각했으나 **깃액션으로 매일 자동화**. 이미지 생성은 NVIDIA 오픈소스, 텍스트는 수동, URL로 저장. HTTP→HTTPS 전환.

**진행** → [10-marketing-automation.md](10-marketing-automation.md)
- `scripts/marketing/daily-snapshot.mjs`: 수집→조언→upsert. 매일 08:20 KST cron.
- 지표 스코프 버그: Meta API는 since/until 없으면 하루치만 반환 → **30일 윈도우**로 고정. 쓰레드 상위글은 리포스트가 0이라 **조회수 기준 정렬**.
- 토큰 자가치유: 인스타/쓰레드 만료 10일 전 자동 갱신 → `marketing_tokens`에 재저장. (광고 토큰은 시스템 사용자 토큰 권장)
- 이미지: NVIDIA FLUX(`flux.1-dev`), `image-recipes.json` 단일 소스. Supabase Storage `marketing-images` 버킷. 관리자에 **"이미지 생성" 버튼**.
- HTTPS: Let's Encrypt + nginx, 운영 base `https://api.themuselab.kr/api/v1`. → [09-frontend-integration.md](09-frontend-integration.md)

## 4. 백엔드 최적화 (관리자 통계 + 소비자 조회 속도)

**요청**: 백엔드 최적화, 특히 API 조회 속도(지도에 많은 샵 뿌리는 소비자 경로가 생명).

**진행**:
- **중복 페이지네이션 통합**: 통계 6곳의 1000행 페이지네이션 복붙 → `fetchAllRows` 헬퍼(같은 버그 재발 차단).
- **`listPartnerShops`**: 2단계로 바꿨다가 소규모라 역효과(측정) → 단일 쿼리로 원복.
- **`dashboardSummary`** ↔ SSE `buildSummary` 중복 제거.
- **인덱스**: RDS(created_at·status) 적용 완료. Supabase(`events(event,created_at)` 등)는 `db/migration_perf_indexes.sql` [A] 섹션 — **SQL Editor에서 사용자 적용 필요**.
- **관리자 통계 인메모리 캐시**(2분): 반복 조회 ~28ms(60배↑).
- **소비자 카탈로그 캐시(핵심)**: 운영에 Redis가 없어 `NullCacheService`(no-op) → 카탈로그가 완전 무캐시였음. `InMemoryCacheService`(LRU+TTL, 상한 300 — EC2 912MB)로 교체 + **지도 좌표 격자 스냅**(팬/줌 캐시 공유). 지도 조회 300~800ms → ~52ms.

## 6. 관리자에서 쓰레드 직접 답글/글 발행

**요청**: 토큰에 답글·게시 권한이 있으니 관리자 페이지에서 직접 답글 등록·글 작성. 새 글은 **주제를 주면 원장님 말투로 초안 추천**해 수정 후 발행.

**진행**:
- 권한 확인: 답글/글 컨테이너 생성 성공(발행 권한 있음). **단 API 삭제 권한은 없음(code 10)** → 등록한 글은 앱에서 직접 삭제해야 함.
- `ThreadsPublishService`: 토큰을 `marketing_tokens`에서 읽어 컨테이너 생성 → `threads_publish` 2단계.
  - `POST /admin/marketing/threads/reply` (댓글에 답글)
  - `POST /admin/marketing/threads/post` (새 글 발행)
  - `POST /admin/marketing/threads/draft` (주제→초안, 우리 글 말투 학습). 서버 Gemini 호출 위해 **EC2에 `GEMINI_API_KEY` 추가**.
- 관리자 UI: 상세 모달의 추천 답글을 **편집→등록**. "새 글 작성"은 주제→초안 추천→수정→발행.

**요청**: 원장님 대상 게시글 초안. "요즘 자동화 도와준다는 전화·DM 영업 많은데, 그 자동화를 샥이 실제로 만들고 있고, 이미 예약을 실제로 이어준 검증된 이력이 있으니 우리를 써달라." → 이후 "운영+빈자리 둘 다 하는 건 우리뿐, 손님 앱 개발 막바지→곧 원장님 앱 제작" 추가. → 다시 "원장님들에게 어떤 기능이 필요한지 직접 묻는 참여형". 자랑할 숫자(누적 방문자/MAU/DAU/예약 클릭)도 요청.

**진행**:
- 초안: 원장님 실제 글 톤을 학습해 여러 버전 생성(공감형/대비형/참여형).

  - ⚠️ `예약 클릭`은 "버튼 클릭"이지 "확정 예약"이 아님 → "예약 성사" 표현은 과장. "예약 클릭/연결" 로만 사용.

## 8. 🔴 Supabase 프로젝트 정지 (egress 초과) — 2026-08-05

**증상**: `themuselab/syak`의 모든 워크플로가 하루종일 실패(slot-ingest, price-sync, partner-sync, today-open-refresh, discord-report). 8~40초 만에 fail.

**원인**: 깃액션 문제가 아니라 **Supabase 프로젝트 정지**. REST/Storage 전부 **402 Payment Required**:
> `Service for this project is restricted ... exceed_egress_quota. The project owner must upgrade their plan or remove spend caps to restore service.`

무료티어 월 egress(전송량) 5GB 초과. 그래서 Supabase를 읽는 **앱·관리자·스크래퍼가 전부 중단**.

**중요 구분**: 이건 **저장 용량(디스크)이 아니라 egress(전송량)** 초과다. **데이터를 지워도 이미 쓴 egress는 안 돌아오므로 서비스 복구 안 됨.**

**복구 방법(사용자 조치)**:
1. Supabase Pro 업그레이드 또는 spend cap 해제 → 즉시 복구.
2. 다음 결제 주기까지 대기 → 그동안 서비스 중단.

**egress 절감(미래 대비, Claude가 도울 수 있음)**: 소비자 캐시 확대(일부 완료), 스크래퍼 변경분만 저장(현재 슬롯 전량 삭제→재삽입), 통계 집계를 DB로 푸시.
