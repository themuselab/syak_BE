## 근거와 원인

운영 DB의 마사지 분류 및 실제 네이버 PlaceDetailBase.category를 대조했다. 의심 상호 43종을 확인했으며, 동일한 정수기·비데·마사지기 렌탈 상호가 마사지 데이터에 279개 있었다. 이름의 단어 또는 마사지 메뉴 존재만으로 마사지 업종을 인정하지 않는다.

`enrich_details.extract_detail`은 `category_detail`을 수집하지만 기존 `build_read_model.build_summary`는 이를 사용하지 않고 입력 `categories`를 그대로 투영했다. 검색어 기반 최초 분류가 잘못 들어왔을 가능성과 별개로, 실제 원본 업종을 재검증하지 않는 투영 결함은 코드에서 확인됐다. 최초 전국 검색 수집기 전체는 현재 레포에 없어 최초 오분류 생성 지점까지 확인했다고 주장하지 않는다.

- `db/migration_shop_suppressions.sql`: shop_suppressions와 BEFORE INSERT/UPDATE 트리거. 삭제 ID는 재삽입할 수 없으며 기존 데이터 덤프 재적재에도 적용된다. ID와 사유만 보존한다.
- `shop_category_overrides`: 검증된 4곳의 분류가 이전 수집 결과로 덮어써지는 것을 방지.
- API 공개 목록·상세·빈자리 조회와 수집 타깃에 기존 제외 정책을 확장. 캐시에 제거 대상이 있으면 목록을 다시 조회한다.
- 웹 read-model 신규 생성은 마사지 원본 업종을 확인하고 피부·체형관리는 피부로 변환. 제조·판매·재활·불명확 업종은 마사지 read-model 생성을 거부한다. 원본 업종도 산출물에 보존한다.
- SEO regions 데이터는 변경된 운영 DB로 재생성. 삭제 ID가 결과에 없는지 확인한다.
- DB 재삽입 시도와 잘못된 업종 덮어쓰기 시도는 트랜잭션 롤백으로 검증.
